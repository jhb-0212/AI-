### 修复内容

1. **Track 数据类型 bug**（关键）：站点从网易云迁到 QQ 音乐后，歌曲 ID 变成字符串 songmid（如 `001if23h0TDFmD`），但 `Track.netease_id` 仍是 `Integer`，`seed.py` 里 `int(track["id"])` 对字符串抛 `ValueError`，导致后台启动即失败（测试 20 errors）。
   - 字段改名 `netease_id` → `song_id`，类型 `Integer` → `String(64)`。
   - 同步改 `models.py`、`schemas.py`、`render.py`、`seed.py`、`admin.js`、两个测试文件。
   - 新增 `server/migrate_tracks.py`：一次性迁移脚本，用「重建表」方式把老库 `netease_id`（INTEGER）改成 `song_id`（TEXT）并对齐 songmid，幂等。

2. **凭证泄露**（严重）：
   - `music.py` 硬编码的网易云/QQ 音乐 Cookie 改为环境变量 `NETEASE_COOKIE`/`TENCENT_COOKIE`，缺省退化为试听。
   - `.gitignore` 补 `server/data/backups/`，`git rm --cached` 移除已追踪的数据库备份 `db-20261109.sqlite`。
   - ⚠️ 需用户自行作废已泄露的两个音乐平台登录态。

3. **鉴权漏洞**：`content.py` 的 `/api/upload-image` 接口补上 `dependencies=[Depends(current_user)]`（原来未认证可上传）。

4. **字段漂移 bug**：前端用了 `site.musicServer`（index.astro/music 页），但后端 `schemas.py`/`render.py`/`seed.py`/`site.py` 均缺失该字段，导致后台发布会丢失 `musicServer`。已全链路补齐，并同步数据库 Setting 到文件最新值（`playlistId=9779561294`、`musicApi=http://127.0.0.1:8000/api/music`、`musicServer=tencent`）。

## 安全风险审查 + 第二轮修复

针对安全做了系统性审查，修复了 4 个中高风险点：

1. **默认管理员密码**（高）：`config.py` 现在强制 `ADMIN_PASSWORD` 必须显式设置且不能是 `nepenthe-admin`，否则启动报 `RuntimeError`。三种情况（未设/默认值/正常值）已验证。

2. **前台存储型 XSS**（高）：Astro 默认 `rehype-raw` 让 Markdown 里的 raw HTML 原样渲染。新增 `src/plugins/rehype-sanitize.mjs`：在 raw HTML 解析前把 `raw` 节点整段转义、`element` 节点过滤危险标签（script/iframe 等白名单外）和危险属性（on*、javascript:、data:、vbscript:、file: 协议）。已验证 `<script>alert`、`onerror`、`data:text/html`、`<iframe>` 全部被转义为无害文本，而 callout/mark/加粗等安全内容保留。
   - **关键坑**：Astro 的 rehype 管线顺序是 `remarkRehype(allowDangerousHtml:true) → 用户 rehypePlugins → rehypeRaw → stringify`，所以 sanitize 必须同时处理 `raw` 节点（rehypeRaw 之前还是字符串），只处理 element 会漏。另外 `.astro` 缓存会导致改插件后构建不生效，需 `rm -rf dist` 强刷。

3. **X-Forwarded-For 伪造**（中）：`visits.py` 改为受控解析，新增 `TRUST_PROXY` 环境变量（默认关闭），只在显式配置时才读 XFF，否则用连接对端 IP。

4. **音乐代理滥用**（中）：`music.py` 加 `server` 白名单（netease/tencent）、`id` 格式校验（`^[A-Za-z0-9]{1,32}$`）、IP 限流（每分钟 60 次）。

验证：pytest 29 条全过，Astro 构建 17 页成功。

## 音乐模块播放慢排查 + 修复

用户反馈音乐「播放太慢」。排查根因（不止是慢，是部分歌根本放不出）：

1. **流式代理 bug（核心）**：`music.py` 的 `stream_audio` 是惰性生成器，却引用外层 `async with httpx.AsyncClient(...)` 的 `client`；函数返回时 client 已关闭，生成器被 StreamingResponse 调用时抛 `RuntimeError: Cannot send a request, as the client has been closed`。即**流式代理从未正常工作**。修复：生成器内独立开 `httpx.AsyncClient`，并带上 QQ 音乐音频下载需要的 Referer。

2. **QQ 音乐拿不到 purl**：`music.py` 写死 `loginflag: 1`，无 Cookie 时部分歌拿不到试听。改为按有无 `TENCENT_COOKIE` 动态：有 Cookie 用 1（完整歌曲），无 Cookie 用 0（更宽松拿试听）。同时修 `uin` 和 `sip`（播放服务器地址，返回的 sip 列表第一个，缺省用 `dl.stream.qqmusic.qq.com`）。

3. **版权限制明确化**：QQ 返回 `result: 104003`（VIP/版权）时，返回明确 error「需配 TENCENT_COOKIE」而不是空 error。

4. **Meting 回退逻辑 bug**：Meting 的 `url` 接口对 netease 返回的是音频二进制流（Content-Type: audio/mpeg），不是 JSON/URL。原来当 JSON 解析会失败。已区分：JSON 含 url 字段用 url，audio/* 则直接透传音频流。

实测：`003Hmybe1Jax5h`（杀死那个石家庄人）无 Cookie 也能拿到完整 1.98MB m4a 音频流；`001if23h0TDFmD`（陀飞轮，版权受限）返回明确错误。

### 结论 / 遗留

- QQ 音乐版权受限歌曲（如陀飞轮、奇妙能力歌）无 Cookie 拿不到，**必须配 `TENCENT_COOKIE`（含登录态）**才能播完整歌曲，代码层面无法绕过 QQ 版权校验。
- `site.data.json` 的 `musicApi=http://127.0.0.1:8000/api/music` 是本地开发配置；上线后要改成走 nginx 反代的 `https://域名/api/music`（nginx 已配 `/api/` 反代到 8100）。
- README 环境变量表补了 NETEASE_COOKIE / TENCENT_COOKIE / TRUST_PROXY / BACKUP_DIR / BACKUP_REMOTE_KEEP_DAYS。
